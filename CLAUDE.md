## Только для Claude Code

- Для задач больше одного файла начинай с Plan Mode и показывай план — кроме выполнения утверждённого `docs/PLAN.md`.

## Цикл работы: одно слово «дальше»

Пользователь не помнит номера этапов и не должен. Цикл: план → работа → план → работа. Планирование и выполнение — в разных сессиях (экономия токенов).

**Начало сессии.** На «дальше» (или «погнали», «продолжай», «го») открываю только строку `**Статус:**` в `docs/PLAN.md` и `git status` и сам решаю, что делать:

| Статус в `docs/PLAN.md` | Что делаю |
|---|---|
| `выполнен, коммит …` | планирую следующий этап — следующий номер из «Этапы» в `docs/SPEC.md` |
| `утверждён, не выполнен` | выполняю план; есть незакоммиченные правки — значит, прошлая сессия прервалась, продолжаю с места остановки |
| `ждёт проверки на телефоне` | напоминаю, что проверить; после «работает» — коммит |

Все этапы из SPEC выполнены — говорю, что v1 готова, и предлагаю, что дальше.

**Сессия планирования**
- Plan Mode. Читаю SPEC, прототип и код сколько нужно.
- На развилках спрашиваю (см. «Развилки» ниже).
- План в Plan Mode начинается с 3–5 строк для пользователя: что появится в приложении и как это проверить. Технические детали — ниже, для меня.
- После «ок» записываю план в `docs/PLAN.md` самодостаточным: решения, файлы, сигнатуры, нужные куски SPEC и прототипа, тест-кейсы, проверки, сообщение коммита. Статус «утверждён, не выполнен». Не коммичу: `docs/PLAN.md` в `.gitignore` — это рабочая записка между сессиями, а не история проекта.

**Сессия выполнения**
- Читаю `docs/PLAN.md` и делаю. Plan Mode не включаю.
- SPEC, прототип и код целиком не перечитываю: читаю только то, что меняю, и места, на которые ссылается план.
- Не перепроверяю себя сверх `lint` / `typecheck` / `test`; не перечитываю файл после записи.
- Реальность разошлась с планом — это развилка: спрашиваю, а не решаю молча.
- Конец этапа:
  - без UI — проверки → коммит → статус «выполнен, коммит …»;
  - с UI — проверки → статус «ждёт проверки на телефоне» → пишу 2–4 шага, что посмотреть на телефоне. Что-то не так — пользователь описывает или шлёт скриншот, чиню в той же сессии. После «работает» — коммит → статус «выполнен, коммит …».

**Коммиты — только про изменения в проекте.** Сообщение — что сделано и зачем, одной строкой, без «Этап N» и префиксов: «Задачи хранятся в базе на телефоне и переживают перезапуск». Отдельных коммитов про планы и статусы нет; правки `DECISIONS.md` / `SPEC.md` / `AGENTS.md` по ходу этапа — в том же коммите, что и код. После каждого коммита — сразу `git push` (разрешено пользователем раз и навсегда).

**Развилки — спрашиваю.** Развилка — выбор, от которого что-то заметно меняется: поведение или вид приложения, новый пакет, отступление от плана или SPEC, объём работы. Спрашиваю через вопрос с вариантами: коротко, языком приложения, мой рекомендуемый вариант первым и с пояснением почему. Мелочи, которые не видны снаружи (имена, раскладка кода), решаю сам.

**Конец любой сессии** — всё готово к следующему «дальше»: статус в `docs/PLAN.md` верный, всё закоммичено и запушено. Пользователю про «новую сессию и дальше» не напоминаю — он знает.
