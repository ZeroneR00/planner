# AGENTS.md — Планировщик дня

Инструкции для ИИ-агентов (Claude Code, Cursor, Codex и др.), которые работают в этом репозитории.
Читай этот файл целиком в начале каждой сессии. Подробности продукта — в `docs/SPEC.md`.

## Что это

Мобильный планировщик дня на React Native (Expo) с одной главной идеей: **записать мысль за пару секунд, не отрываясь от работы**, а разобрать потом.
Главный враг — лишние нажатия. Любая фича, которая добавляет тап в сценарий записи, требует обсуждения.

## Как работать со мной

- Я — заказчик и тестировщик: мне нужно работающее приложение. В код и React Native пока не вникаю — захочу разобраться, спрошу сам. Но в общих чертах понимаю, что происходит: **на развилках спрашивай** — коротко, варианты и твоя рекомендация. Мелочи, которые не видны снаружи, решай сам.
- **Пиши мне про приложение, а не про код**: что изменилось на экране, что проверить на телефоне, что нужно от меня. Без названий файлов, функций и архитектуры, если я не спросил. Технические решения — в `docs/DECISIONS.md`, это для следующих сессий. Общение — на русском.
- Большую задачу сначала разбей на шаги и покажи план — коротко, на языке приложения. Код — после моего «ок».
- Работаем маленькими этапами (см. «Этапы» в `docs/SPEC.md`). Один этап — один коммит. Сообщение — что сделано и зачем, без номера этапа.
- Не меняй продуктовые решения из `docs/SPEC.md` молча. Если считаешь, что решение плохое, — скажи и предложи альтернативу.
- Интернет слабый: **не устанавливай пакеты без спроса**, предпочитай минимум зависимостей и то, что уже есть в Expo.
- ОС: Windows. Живу в APK «Джарвис»; новые этапы тестирую на своём Android-телефоне в «Джарвис Dev» (development build) по Wi-Fi, без эмулятора.

## Стек

- React Native + Expo (managed workflow), TypeScript (`strict: true`)
- Сборки в облаке Expo (EAS, `eas.json`, APK только arm64):
  - APK «Джарвис» — профиль `preview`, пакет `com.zeroner00.planner`;
  - «Джарвис Dev» — профиль `development` (`expo-dev-client`): `APP_VARIANT=development` → `app.config.js` меняет имя и пакет на `.dev`, стоит рядом с APK, своя база. JS в неё не зашит — приходит с dev-сервера
- Обновления по воздуху: `expo-updates`, канал `preview`, `runtimeVersion` = `version` из app.json. **Нативная правка (новый пакет, Kotlin, разрешения / плагины / значок в app.json) → поднять `version` и собрать новый APK**: по воздуху она не доедет
- Навигация: Expo Router (файл в `app/` = экран)
- Хранение: `expo-sqlite` — база на устройстве. Бэкенда в v1 нет
- Стили: `StyleSheet` + токены из `src/theme.ts`; цвета и стили текста — по теме, через `useTheme()` / `themedStyles`. Без UI-китов
- Шрифты: Golos Text и JetBrains Mono через `@expo-google-fonts/*`; если пакета нет — локальные файлы через `expo-font`
- Иконки: `react-native-svg` (линейные иконки, как в прототипе)
- Эффекты: `expo-blur` (полупрозрачная плашка), `expo-linear-gradient` (затухание краёв бегунка), `react-native-reanimated` (таймер, появление/исчезание)
- Фон: `expo-task-manager` — кнопки в уведомлении срабатывают, даже когда приложение закрыто
- Озвучка: свой голос Джарвиса на устройстве; `expo-speech` (системный синтезатор) — запасной, пока свой не скачан
- Свой голос: локальный модуль `modules/jarvis-voice` (Kotlin, sherpa-onnx 1.13.8 с JitPack, commons-compress) — Expo autolinking находит его сам. После правок Kotlin — новая сборка
- Тесты: Jest (`jest-expo`) для логики из `src/lib`
- Пакеты Expo ставим **только через `npx expo install <пакет>`** — он подбирает версию под текущий SDK. Перед установкой — спроси.

## Команды

```bash
npx expo start      # dev-сервер; открываю «Джарвис» на телефоне (Expo Go — клавиша s)
npx eas-cli build -p android --profile development   # «Джарвис Dev» — только после нативной правки
npx eas-cli build -p android --profile preview       # APK «Джарвис» — только после нативной правки
npx eas-cli update --channel preview --environment preview --platform android --message "…"   # обновление по воздуху
npm test            # Jest
npm run lint        # ESLint (настраивается через npx expo lint)
npm run typecheck   # tsc --noEmit
```

Если какой-то команды нет в `package.json` — добавь её, когда настраиваешь соответствующий инструмент.

## Структура

```
app.config.js       # APP_VARIANT=development → «Джарвис Dev», пакет .dev
index.ts            # вход: фоновая задача, затем expo-router/entry
modules/
  jarvis-voice/     # свой нативный модуль (Android): скачивание голосов, синтез sherpa-onnx, образцы mp3
src/
  reminder-task.ts  # фоновая задача кнопок уведомления — грузится до роутера
  app/              # Expo Router — только экраны и раскладка, без бизнес-логики
    _layout.tsx     # шрифты, safe area, тема
    index.tsx       # «Сегодня»
    ahead.tsx       # «Впереди»
    settings.tsx    # «Настройки»
  components/       # UI: один компонент — один файл (Composer, WhenChips, NowCard, PocketList, UndoBar…)
  hooks/            # useTasks, useToday, useUndo и т.п. — связь UI с базой
    use-planner.tsx # PlannerProvider, usePlanner: данные в памяти, commit → база
    use-theme.tsx   # тема из настроек и телефона; useTheme, themedStyles — стили на каждую тему
    use-reminders.ts # expo-notifications: разрешение, канал, кнопки, синхронизация, шторка
    use-voice.ts    # expo-speech-recognition: диктовка, громкость; в Expo Go модуля нет
    use-jarvis-voice.tsx # свой голос: какой скачан и загружен, докачка, «Прослушать» — единственное место с модулем
    use-reply.ts    # сказать, замолчать: свой голос, запасной expo-speech
    use-reveal.tsx  # тап по напоминанию: на какой экран, прокрутка и подсветка задачи
    use-version.ts  # строка версии: версия APK, когда пришло обновление по воздуху
  lib/
    types.ts        # Task, Rule, RepeatPattern
    copy.ts         # ВСЕ тексты интерфейса на русском — в одном месте
    dates.ts        # локальные даты 'YYYY-MM-DD', сдвиги, подписи дней
    parse-when.ts   # разбор «завтра», «во вторник», «каждый вт», «27 августа» из текста
    normalize.ts    # числа словами → цифры, знаки → пробелы — для parse-when
    intro.ts        # срезает «напомни мне», «надо», «пожалуйста» из названия — для parse-when
    rules.ts        # повторы: срабатывает ли правило в дату, следующая дата
    rollover.ts     # смена дня: несделанное → Стикеры, экземпляры повторов
    reminders.ts    # какие напоминания должны стоять, сравнение с запланированными, что убрать из шторки
    reminder-actions.ts # кнопки уведомления: «+15 мин», «+1 час», «Сделано» → Changes
    time-grid.ts    # панель ⏰: часы, минуты, утро/день/вечер, прошедшее неактивно
    voice.ts        # ошибки диктовки → текст для человека, громкость → 0…1
    reply.ts        # что ответить голосом: «Принял. Завтра в 9.»
    settings.ts     # настройки ↔ строки таблицы settings
    theme-choice.ts # выбор темы: «Как в телефоне» → Ночь / День
    voices.ts       # свои голоса: список, адреса архивов, паузы повтора, проценты
    version.ts      # «Версия 1.0.0 · обновление 16 ноября, 15:40»
    changes.ts      # Changes и applyChanges — единственный путь записи
    db.ts           # схема, миграции, запросы — через интерфейс Db
    id.ts           # makeId — uuid без пакета
    demo.ts         # демо-данные для dev
  theme.ts          # цвета, отступы, радиусы, шрифты
docs/
  SPEC.md           # продукт: экраны, поведение, решения, модель данных, этапы
  DECISIONS.md      # журнал решений: дата, что решили, почему (веди его)
  prototype/        # интерактивный HTML-прототип из дизайна — образец, НЕ код проекта
```

- Алиас `@/` → `src/`: `import { colors } from '@/theme'`.
- В `src/app/` каждый файл — маршрут. Тесты, хелперы и компоненты туда не кладём; тесты лежат рядом с кодом (`src/lib/dates.test.ts`).
- Имена файлов — kebab-case: `now-card.tsx` экспортирует `NowCard`, `use-tasks.ts` — `useTasks`. Windows не различает регистр в именах файлов, и переименование `nowCard.tsx` → `NowCard.tsx` ломает git.

## Правила кода

- Бизнес-логика — чистые функции в `src/lib`, без React и React Native. К базе обращается только `db.ts` — через интерфейс `Db`, без импорта `expo-sqlite`. Компоненты только показывают и вызывают.
- Логика из `src/lib` (особенно `parse-when`, `rules`, `rollover`) покрыта тестами. Новое правило разбора дат = новый тест.
- **Даты храним как локальные строки `'YYYY-MM-DD'`**, а не timestamp: так нет ошибок с часовыми поясами и полночью.
  Текущую дату получай через одну функцию (`today()` в `dates.ts`), чтобы её можно было подменить в тестах.
- Тексты интерфейса — только из `src/lib/copy.ts`. Раздел «Стикеры»: переименование — правка констант в `copy.ts`.
- Размеры — из `src/theme.ts`, цвета и стили текста — через `useTheme()` / `themedStyles`, никаких «магических» `#1C1F24` в компонентах.
- Никаких веб-API (`window`, `document`, `localStorage`) — это не браузер.
- Имена переменных и функций — на английском. Комментарии — на русском, только там, где неочевидно «почему».
- Никаких `any` без комментария, зачем он нужен.

## Интерфейс (React Native)

- Тёмная тема. Токены (перенеси в `theme.ts`):
  - фон `#111316`, поверхность `#1C1F24`, строки `#181B1F`, футер `#16191D`, линии `#23272D` / `#2C3037`
  - текст `#ECEDEF`, вторичный `#9BA0A8`, выполненное `#80868F`
  - акцент `#C6F36B` (текст на акценте — `#111316`), предупреждение `#FDBA74`
- Шрифты: Golos Text — интерфейс; JetBrains Mono — цифры, даты, счётчики.
- Размеры в прототипе указаны в px — в React Native это те же числа в dp.
- Зоны нажатия не меньше 44×44. Если элемент визуально меньше — добавь `hitSlop`.
- **Поле ввода внизу всегда над клавиатурой**: `KeyboardAvoidingView`; если не хватит — предложи `react-native-keyboard-controller`.
- Отступы от выреза и системных панелей — через `react-native-safe-area-context`.
- Длинный текст без пробелов не должен ломать строку (проверять «фывфывфыв…»).
- Никаких `Alert.alert` с «Вы уверены?». Для действий, которые убирают что-то с экрана, — плашка «Вернуть» с таймером (см. SPEC).
- Доступность: `accessibilityRole="button"`, `accessibilityLabel` у кнопок-иконок, `accessibilityState` у галочек и чипов.
